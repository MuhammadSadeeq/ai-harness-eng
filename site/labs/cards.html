Six cards, one of each type. A right answer waits longer; a miss comes back today.

Demo cards

The fronts and backs of the six demo cards. With JavaScript on, you answer each one here.

  1. What is the almost-done spiral?

    A run that keeps calling tools and never reaches an exit. The loop has one way out, and the model never takes it. A second exit, such as a turn limit, stops the run.

  2. The agent says the bug is fixed. Nobody ran the tests. Which wire is that?

    Verification and evals. A done claim is only a claim until a check runs, and this run never ran one.

  3. A tool returns 200 KB of log text, and the next model call carries all of it. The task is now buried. Which wire holds this problem?

    Context and memory. One giant tool output fills the window. Cap it, keep the full text outside the window, and send a short summary.

  4. The model asked for read_file with the id toolu_1. The next message answers with the id toolu_2. Pick the row that breaks the pair.

    The result names toolu_2, so the call toolu_1 has no result. That is an orphaned tool call, and the API rejects the next request. Every tool_use needs a tool_result with the same id in the next user message.

  5. Put one turn of the loop in order. The results go back in the next message, matched by id.

    Call the model, read why it stopped, run the tools after the permission check, then send every result back in one message, matched by id. Then the loop repeats or exits.

  6. Read the trace. Which failure family is it?

    Approval fatigue. So many prompts arrive that the dangerous one, rm -rf data/cache, is approved in a second without a look. Fewer, clearer prompts give each one a real look.
