A

agent

A model that is called in a loop, asks for tools, and is stopped by the code around it. The model is one part of the agent.

Loop Taught in S0 · Same model, different harness

Also written: agents

agent loop

The code that calls the model, runs the tools the model asks for, adds the results to the history, and calls the model again. It stops when one of its exits is taken.

Loop Taught in B2 · The agent loop

Also written: agent loops

C

context window

The fixed-size desk the model reads on each call. Instructions, earlier messages, tool results and the reply all share it.

Context Taught in A2 · Tokens and the context window

Also written: context windows

conversation history

The earlier messages in the list. The harness keeps them, and decides how much of them each call sends.

Context Taught in A3 · The stateless model

Also written: history

coroutine

What an async def function returns when you call it.

Not on a wire Taught in T2 · asyncio

Also written: coroutines

D

dataclass

A Python class that holds named fields. The @dataclass decorator writes the __init__ method, so Rein can build a reply with named fields.

Loop Taught in H1 · Rein 1: talk to a model

Also written: dataclasses

done claim

The model's own statement that it has finished, carried by end_turn. The loop treats it as a claim to check. It is not proof that the task is done.

Loop Taught in B2 · The agent loop

Also written: done claims

E

exit

A reason the loop stops. A loop with one exit stops only when that one exit is taken.

Loop Taught in B2 · The agent loop

Also written: exits

F

failure family

A named kind of failure that recurs across runs, such as a false done. Each module teaches one family.

Verification Taught in S0 · Same model, different harness

Also written: failure families

H

hallucination

A fluent, specific claim that is false. The reply reads the same as a true one, so reading it does not reveal the error.

Verification Taught in A1 · What a model does

Also written: hallucinations

harness

Everything around the model: the loop, the tools, the permissions, the checks and the limits. Same model, different harness, different results.

Control Taught in S0 · Same model, different harness

Also written: harnesses

Harness Board

The harness's settings, such as limits and gates, shown next to what a run does.

Control Taught in S0 · Same model, different harness

Also written: Harness Boards

I

inference

A model call that reads the weights and the prompt and produces a reply. The weights stay the same during inference.

Control Taught in A1 · What a model does

input tokens

The tokens the model reads on a call: the instructions, the earlier messages, the tool results and the new message.

Context Taught in A2 · Tokens and the context window

Also written: input token

L

language model

A model that reads a text and scores the possible next tokens. A harness calls it again and again, and each call gives one reply.

Loop Taught in A1 · What a model does

Also written: language models

latency

How long a call takes to finish. More tokens in and out usually mean a longer wait.

Loop Taught in A2 · Tokens and the context window

M

memory

Anything a run can use later: what is in the window, what is in saved files, or what is in the model's weights.

Context Taught in A3 · The stateless model

Also written: memories

messages array

The ordered list of messages sent with each call. It is the conversation the model can see.

Context Taught in A3 · The stateless model

Also written: messages arrays, messages list

model interface

One function that Rein calls to get a reply. A scripted model and a real model both sit behind it, with the same inputs and the same kind of result.

Loop Taught in H1 · Rein 1: talk to a model

Also written: model interfaces

N

next-token prediction

The model's one job on each step: score every possible next token. Nothing in this step checks whether a token is true.

Loop Taught in A1 · What a model does

Also written: next token prediction

O

output limit

The most tokens one reply may use. A reply that reaches it stops there, and the reply says why.

Control Taught in A2 · Tokens and the context window

Also written: output limits

output tokens

The tokens the model writes in its reply. They use the same window as the input.

Context Taught in A2 · Tokens and the context window

Also written: output token

P

pass rate

The share of trials that pass their checks. It is a measure over many runs, not the result of one.

Observability Taught in S0 · Same model, different harness

Also written: pass rates

probability

A number from zero to one that says how likely a choice is. The sampler turns the scores into probabilities before it picks.

Loop Taught in A1 · What a model does

Also written: probabilities

R

ReAct

A name for the loop of reasoning and acting in turns, from the paper ReAct: Synergizing Reasoning and Acting in Language Models.

Loop Taught in B2 · The agent loop

role

The label on each message in the list. A message is from the user or from the assistant.

Context Taught in A3 · The stateless model

Also written: roles

run

One agent doing one task, from the first model call to a stop. A run has many turns.

Loop Taught in S0 · Same model, different harness

Also written: runs

S

sampling

The step that picks one token from the scored options, by the rules it is given. The model scores; the sampler picks.

Loop Taught in A1 · What a model does

seed

The number that sets the random draws of a scripted run. The same seed gives the same run, every time.

Observability Taught in S0 · Same model, different harness

Also written: seeds

stateless

Keeping nothing between calls. A stateless call starts from what it is sent, and nothing else.

Context Taught in A3 · The stateless model

system prompt

The instructions sent with every call, kept apart from the messages. The harness sends it each time.

Control Taught in A3 · The stateless model

Also written: system prompts

T

temperature

A setting of the sampler that changes how much the scores count. Higher temperature spreads the choice over more tokens. At zero, the top token always wins.

Control Taught in A1 · What a model does

token

A piece of text the model reads and writes. A token is often a word, but it can be part of a word or a punctuation mark.

Context Taught in A1 · What a model does

Also written: tokens

token budget

A cap on the total tokens a run may use, input and output together. The loop checks it before each call and stops when the total has reached the cap.

Loop Taught in B2 · The agent loop

Also written: token budgets

tokenizer

The part that cuts text into tokens. Real tokenizers differ, so a count from the course is an estimate.

Context Taught in A2 · Tokens and the context window

Also written: tokenizers

tool

A function the harness runs when the model asks for it. The model only asks. The harness runs the function and returns the result.

Tools Taught in S0 · Same model, different harness

Also written: tools

tool registry

A table from each tool name to the Python function that runs it. The loop looks up the name the model asked for. A name that is not in the table gets an error result.

Tools Taught in H2 · Rein 2: one tool and the loop

Also written: tool registries

trace

The record of a run: each model call, reply, permission, tool call and check, in order.

Observability Taught in S0 · Same model, different harness

Also written: traces

training

The process that sets the model's weights, from many example texts. It happens before any chat, and a chat does not run it.

Control Taught in A1 · What a model does

trial

One run with one seed. A bench runs many trials of the same setup.

Observability Taught in S0 · Same model, different harness

Also written: trials

turn

One call to the model and the tool results that follow it. A run is a series of turns.

Loop Taught in B2 · The agent loop

Also written: turns

turn limit

A cap on the number of model calls in one run. When the count reaches it, the loop stops.

Loop Taught in B2 · The agent loop

Also written: turn limits

type hint

A note that says what type a name should hold, such as count: int, or -> str after the parameters of a function.

Not on a wire Taught in T1 · Python typing and dataclasses

Also written: type hints

W

weights

The numbers inside the model that set its scores. Training sets them. Inference only reads them.

Context Taught in A1 · What a model does

Also written: weight
