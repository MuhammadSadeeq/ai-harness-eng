A run that forgets what it read

This run reads notes.txt on its first turn. On its second call, it asks for the file again. Predict what the model has when it answers.

Without JavaScript, the question is: the run read notes.txt on its first turn. On its second call, what does the model have when it answers?

  1. Everything from the first call, the file included.
  2. Only the task, because the harness sent nothing else.
  3. A saved copy of the file, kept by the provider.

The model read the file, then asked for it again, and again. Nothing in the model had changed. The harness had sent only the task on each call, so each call started from the task. The run does not get closer to the end. Each call repeats the same work, and only a limit stops it. The next part shows what a call carries.

What a call carries

A model call is a request, and the request holds everything the model can read. Requests are stateless: you send the full conversational history with each request. The model keeps nothing between calls. Whatever it should know must be in the request.

So the harness keeps a list. It holds the task, each reply, and each tool result, in order. That list is the messages array, and the harness sends it with each call. A stateless model reads only what that list holds.

Each entry in the list has a role: the message is from the user or from the assistant. The harness adds each tool result after the reply that asked for it, so the list reads in the order the work happened.

Some things sit apart from the list. The system prompt holds the instructions. The docs say a system prompt is a way of providing context and instructions to Claude, such as specifying a particular goal or role. In this course, the harness puts the system prompt in front of every call.

The earlier messages that the harness keeps are its conversation history. The harness decides how much of that history each call sends. Send all of it, and the model can use it. Send none, and the model starts from the task.

When a run goes wrong, open the list that was sent on the failing call. Look for the result the model needed. Either it is in the list or it is missing, and that answers most questions about a run that forgot.

messages = [{"role": "user", "content": "Read notes.txt."}]
messages.append({"role": "assistant", "content": "Reading it now."})
messages.append({"role": "user", "content": "The file says apples 3."})
print(len(messages), [m["role"] for m in messages])
3 ['user', 'assistant', 'user']

Run the snippet. Then add one more message, and run it again.

Without JavaScript, the question is: why does each model call start from nothing?

  1. The model forgets, the way people do.
  2. The model keeps no state between calls. Each call starts from what the harness sends.
  3. The provider deletes the conversation after each call.

Without JavaScript, the question is: for the model to use the result of a tool call on the next call, what must the messages array hold?

  1. Only the new user message.
  2. The earlier assistant message and the tool result that follows it.
  3. A file path where the result was saved.

Prove it on the same seeds

The old board has the history switched off. The new board sends it. Both boards run on the same 20 seeds, so the setting is the only difference.

The only difference between the two boards is the history setting. The task, the tools, the model and the seeds are the same. So a gap in the pass rate comes from the history, and from nothing else in this bench.

These runs are scripted, so they repeat exactly. Real models vary, and later modules measure that.

Keep it

The messages array is the memory.

A run can use memory in three places. The window holds what one call reads. Saved files hold what the harness writes to disk and reads back later. The weights hold what the model learned in training. The harness controls the window and the saved files. It does not control the weights.

Without JavaScript, the question is: which kind of memory belongs to the model's weights?

  1. What the model learned in training.
  2. What the harness writes to saved files.
  3. What is in the window for this call.
What does stateless mean for a model call?
The call starts from what it is sent, and nothing else.
What is the messages array?
The ordered list of messages sent with each call. It is the conversation the model can see.
What is conversation history?
The earlier messages in the list. The harness keeps them and decides how much each call sends.
