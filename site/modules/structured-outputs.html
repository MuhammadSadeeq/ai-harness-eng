A write with the wrong shape

The model asks to add a name to a file. Its request uses a field the tool does not have. Predict what the harness does with it.

Without JavaScript, the question is: the model asks to write names.txt, with the new names in a field called text. The harness has no check. What happens?

  1. The harness refuses the call and asks the model for the right field.
  2. The write runs with no content, and the file is written empty.
  3. The write runs, and the new names are saved under the field text.

The file was written empty, and the names were gone. Nothing compared the request with the tool's schema. The run ended as done, and the checks failed.

What a schema says

A JSON Schema writes down the shape of a value: its fields, their types, which fields are required, and which values are allowed. A schema for a write has a required path and a required content, and nothing else.

schema = {"properties": {"path": {"type": "string"}, "content": {"type": "string"}},
          "required": ["path", "content"], "additionalProperties": False}
print(schema["required"], schema["additionalProperties"])
['path', 'content'] False

With additionalProperties set to false, a field the schema does not name is refused. Each enum field may take only one of its listed values.

Without JavaScript, the question is: in this course's checker, which keyword lists the fields that must be present?

  1. enum
  2. required
  3. additionalProperties

Structured output from a model

A structured output is a reply in a shape you asked for. Structured outputs is generally available on the Claude API. JSON outputs are requested with output_config.format of type json_schema.

There are three ways to get a shape. You can ask for it in the prompt. You can validate each reply afterwards. Or you can use constrained decoding, which limits what the model can choose while it writes. Each one has a different place where the shape is checked.

Without JavaScript, the question is: which way of getting structured output checks the shape after the model has answered?

  1. Asking for JSON in the prompt.
  2. Validating afterwards, against the schema.
  3. Constrained decoding.

Checking a value against a schema before the harness uses it is schema validation. A validation error is a message the model can use. The reason names the field, so the model knows what to change. Write check_value, which returns the first reason a value fails. Its tests follow the rules in the order the checker applies them.

Without JavaScript, the question is: a schema check says the field content is missing. What should the harness send back to the model?

  1. Nothing; it should run the tool with the missing field empty.
  2. A tool result that says the input is invalid and why, marked as an error.
  3. A new task, so the model starts again.

Keep it

Valid isn't true: check the shape, then the meaning.

A passing check says the shape is right. It says nothing about the values. A strict schema guarantees the shape of a tool call's input. It does not guarantee that the values are correct.

Without JavaScript, the question is: a strict schema guarantees the shape of the input. What does it not guarantee?

  1. That the tool names and inputs match the schema.
  2. That the values are correct.
  3. That the reply is a JSON object.
What is JSON Schema?
A way to write down the shape of a JSON object: its fields, their types, which are required and which values are allowed.
What does additionalProperties false do?
It refuses a field the schema does not name. This course's checker refuses it.
What is schema validation?
Checking a value against a schema before the harness uses it. It returns the first reason the value fails.
