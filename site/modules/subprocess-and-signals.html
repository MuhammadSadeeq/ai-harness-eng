The command is a list

The command in this module is a list of strings: the program, its flags, and its arguments. build_argv builds the list for the kata's script.

def build_argv(script: str, value: int) -> list[str]:
    return ["python3", "-c", script, str(value)]


print(build_argv("print(1)", 4))
['python3', '-c', 'print(1)', '4']

The next blocks start a child process. The page's Run key cannot start one, so these blocks have no Run key. The course's checker runs them on CPython.

# Runs on your machine, not in the browser.
import subprocess
import sys

child = subprocess.run(
    [sys.executable, "-c", "print('hi')"],
    capture_output=True,
    text=True,
    timeout=5,
)
print(type(child).__name__, child.returncode, child.stdout.strip())
CompletedProcess 0 hi

The call returned a CompletedProcess. It has a returncode and a stdout.

# Runs on your machine, not in the browser.
import subprocess
import sys

try:
    subprocess.run([sys.executable, "-c", "import time; time.sleep(5)"], timeout=0.2)
except subprocess.TimeoutExpired:
    print("timed out")
timed out

The call raised TimeoutExpired, so the except block ran.

# Runs on your machine, not in the browser.
import subprocess
import sys

child = subprocess.run(
    [sys.executable, "-c", "import os, signal; os.kill(os.getpid(), signal.SIGTERM)"],
)
print(child.returncode)
-15

Without JavaScript, the question is: the snippet made its child send itself SIGTERM. What did it print?

  1. -15
  2. 15
  3. 0
 
# Runs on your machine, not in the browser.
import subprocess
import sys

code = (
    "import os, signal\n"
    "try:\n"
    "    os.kill(os.getpid(), signal.SIGINT)\n"
    "except KeyboardInterrupt:\n"
    "    print('caught KeyboardInterrupt')\n"
)
child = subprocess.run([sys.executable, "-c", code], capture_output=True, text=True)
print(child.stdout.strip())
caught KeyboardInterrupt

Without JavaScript, the question is: the snippet made its child send itself SIGINT. What did the child print?

  1. caught KeyboardInterrupt
  2. Nothing
  3. A traceback

Write run_checked

Write run_checked in kata.py. It takes a runner, an argument list and a timeout, and it returns the exit code and the output. The tests give it a fake runner that records each call.

Without JavaScript, open katas/T3-timeout/test_kata.py. Each test names one keyword argument, one result or one error.

Keep it

Every child process needs a timeout.

Which keyword arguments does run_checked pass to the runner?
capture_output=True, text=True and timeout=timeout, in one call.
What does run_checked return when the timeout passes?
(None, 'timed out').
Where does the real subprocess.run call go?
On your machine, in your own code.
