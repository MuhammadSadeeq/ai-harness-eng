A loop that asks again and again

Your loop has one tool and no turn limit. Predict what happens to the run next, then read the replay.

Without JavaScript, the question is: your loop has no turn limit, and the model keeps asking for the tests and says it is almost done. What does the loop do?

  1. The model says it is done, and the loop returns.
  2. The loop calls the model again and again, until a person stops it.
  3. The loop stops when the tests pass, because the tests are an exit.

The run went on for many turns. A person stopped it.

The tool, the registry and the loop

The model sees a spec for each tool: the name and what it does. The code that runs the tool lives in a tool registry, a table from each name to its function. When the model asks for a name, the loop looks it up in the registry and runs the function. Nothing else decides what runs.

The loop itself is an agent loop with a turn limit. Read the core of it from the top. The step's code adds logging, but the shape is this.

class Agent:
    def run(self, task):
        messages = [{"role": "user", "content": task}]
        # The turn limit: a hard stop, whatever the model says.
        for turn in range(1, self.cfg.max_turns + 1):
            reply = self.model.call(SYSTEM_PROMPT, messages, TOOL_SPECS)
            messages.append({"role": "assistant", "content": reply.content})
            # No tool requests means the model's done claim.
            if not reply.tool_calls:
                return reply.text
            results = []
            for call in reply.tool_calls:
                output, is_error = self.run_tool(call)
                results.append({"type": "tool_result",
                                "tool_use_id": call.id,
                                "content": output, "is_error": is_error})
            # All results go back together, in one user message.
            messages.append({"role": "user", "content": results})
        return "stopped: turn limit reached"

    def run_tool(self, call):
        try:
            # The registry lookup. An unknown name raises KeyError here.
            return FUNCTIONS[call.name](**call.input), False
        except Exception as e:
            # An error the model can read, not a crash.
            return f"{type(e).__name__}: {e}", True

This loop is the one you read in B2 · The agent loop. Here you write it yourself, with the same exits.

Results go back together, matched by id

The docs say to return one tool_result for each tool_use block, all together in the next user message. A tool_result's tool_use_id is the id of the tool use request that the result answers. The loop appends one message with every result, so the next call sees all of them.

Without JavaScript, the question is: the model asks for two tools in one reply. How many results go back, and where?

  1. One result per request, each in its own user message.
  2. One result for each tool_use, all together in the next user message.
  3. Only the first result, because one tool runs at a time.
  4. None. The model reads the tool output itself.

An unknown tool is an error result

The lookup in the registry can fail, and the loop must not crash on it. A tool_use block that is not run still needs a tool_result with is_error true and a brief explanation. So an unknown name becomes an error result, and the run carries on. The model reads the reason and can change its plan.

Without JavaScript, the question is: the model asks for a tool name that is not in the registry. What should the loop send back?

  1. An exception that stops the run.
  2. A tool_result with is_error set to true, and a short reason.
  3. Nothing. Skip the call and go on.
  4. The same name again, in a new request.

Keep it

The model asks; the harness acts.

What is a tool registry?
A table from each tool name to the Python function that runs it.
What does a tool's spec tell the model, and what does its function do?
The spec describes the tool to the model. The function is the code the harness runs when the model asks for it.
Where do tool results go?
All in one user message, one per tool_use, each with the tool_use_id of its request.
What is a turn limit?
A cap on the model calls in one run. The loop stops when the count reaches it.
Why is one exit not enough?
A loop with one exit stops only when that exit is taken. A model that never takes it runs forever.
What does an unknown tool name get back?
A tool_result with is_error set to true and a short reason. The run carries on.
What does is_error tell the model?
That the result is a failure, so the model can try again or change its plan.
