A run that says it is done

This run edits a file, runs the tests and says it is done. Predict what the harness does next.

Without JavaScript, the question is: the model says the tests pass, and the run ends as done. What does the harness do next?

  1. It runs the checks before it accepts the claim.
  2. It sends the model a message and asks it to run the tests.
  3. It ends the run as done, because nothing checks the claim.

The model said the tests pass. Nothing ran them. The harness took its word, and the run ended as done while the checks failed. This is a failure family that the course calls the false done.

A replay lets you test the claim yourself. Step through the calls and look for a tool action that ran the tests. If there is none, the claim was never checked, whatever the model's last words say.

What a run is made of

One model call gives one reply. An agent needs many calls, so something has to make them. The model is one part of the agent. The rest is the harness: the code that calls the model, runs the tools it asks for, and decides when to stop.

A run is one agent doing one task, from the first call to a stop. A run has many steps, and each one is recorded in a trace, in order.

A seed sets the random draws of a scripted run. The same seed gives the same run, every time. The incident used seed 1, so replay it with seed 1.

Two runs with the same model can end differently. The model is the same. The harness decides what the model sees on each call, which tools it may use, whether a permission is asked, and what happens when the model says it is done. Those choices are settings, and a setting can be changed.

The trace is also how you check a run. Read the last events first. They say how the run ended, and whether anything checked it before it ended.

Change one setting

The new board has a verify gate. When the model says done, the harness runs the checks. If they fail, the model gets the failure and another try. The number of tries is the verify retries setting.

Each trial is one run with one seed. The pass rate is the share of trials that pass. Move the retries and watch it change.

A bench runs the same setup over many seeds. Each seed gives one scripted run, so the two boards meet the same runs. Change one setting at a time. If two settings change together, you cannot tell which one moved the result.

The knob sets the verify retries on the new board. The old board has no verify gate, so the knob does not touch it. The bench marks par: the setting with the lowest worst-case cost that still passes at least as many runs as the old board.

A bench is a comparison, not a verdict. It tells you how this setting behaved on these seeds, and nothing about every task. Before you trust a setting, run it on the seeds your task needs.

These runs are scripted, so they repeat exactly. Real models vary, and later modules measure that.

Check your reading

A pass rate is a number about a setup, not about a model. When you report one, name the setup: the board, the setting and the seeds. Answer each question. The reason for each answer shows after you choose.

Without JavaScript, the question is: in a replay, what is one step?

  1. One line of Python in the harness.
  2. One model call, or one tool action.
  3. One whole run.

Without JavaScript, the question is: the verify retries go from 0 to 1, and the pass rate rises. What does that show?

  1. The model got smarter.
  2. One setting in the harness changed the result, with the model the same.
  3. Every run passed by luck.

Without JavaScript, the question is: two teams use the same model, and one gets far better results. What is the likeliest reason?

  1. Their model is newer.
  2. Their harnesses differ: the loop, the checks and the limits.
  3. They wrote their prompts in a different font.

Keep it

Same model, different harness, different results.

What is a harness?
Everything around the model: the loop, the tools, the permissions, the checks and the limits.
What is a trace?
The record of a run, in order: each model call, reply, permission, tool call and check.
What is a pass rate?
The share of trials that pass their checks. It measures many runs, not one run.
What is a failure family?
A named kind of failure that recurs across runs, such as a false done.

Say it out loud

  1. Change one harness setting and tell me what it did to the pass rate, with your numbers.
  2. A run says it is done. What do you check before you believe it?

Find your way around

Every module page uses the same beats in the same order, so you always know where to look. Core modules have five beats: Break, See, Fix, Prove and Keep. Concept modules have Break, See, Lab, Check and Keep. The eight wires are the parts of a harness: control, context, loop, errors, tools, permissions, verify and observe. Each module names the wires it touches.

Your Harness Board shows the settings of the harness next to what a run does. It is the clock of a run with the limits and gates beside it, so you can see which setting a run reached.

Export your progress from the footer, which saves a file you can import on another device. Then answer the placement questions to see where to start. The answers only suggest a start. Every module stays open.

Without JavaScript, the placement asks fifteen questions about the course and suggests where to start. It is not a test, and every module stays open.
