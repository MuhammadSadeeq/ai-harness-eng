A run that will not stop

This run edits a file, runs the tests and reads the result. It has done that several times. Predict what it does next.

Without JavaScript, the question is: this run has edited and tested several times. What happens next?

  1. The tests pass, the model says it is done, and the run ends.
  2. The loop reaches its turn limit and stops.
  3. It keeps editing and testing until a person stops it.

The model kept saying it was almost done. Nothing in the loop could stop it. A person stopped the run many turns after it went wrong.

How the loop works

One model call gives one reply. An agent needs many calls, so something has to make them. That something is the agent loop. It calls the model, runs the tools the model asks for, and calls the model again. Each pass is one turn: a call, and the results that follow it.

This loop is often called ReAct, after the paper ReAct: Synergizing Reasoning and Acting in Language Models (ICLR 2023): reasoning and acting, in turns.

Read the code from the top. Each comment marks one step.

from collections.abc import Callable
from typing import Any

Reply = dict[str, Any]


def run_loop(model: Callable[[list[Any]], Reply], tools: dict[str, Callable[[Any], str]],
             task: str, max_turns: int) -> str:
    messages: list[Any] = [{"role": "user", "content": task}]
    for _ in range(max_turns):                       # the turn limit: a hard stop
        reply = model(messages)                      # call the model with the full history
        messages.append({"role": "assistant", "content": reply["content"]})
        if reply["stop_reason"] == "end_turn":       # a done claim, not proof
            return "done"
        if reply["stop_reason"] != "tool_use":       # max_tokens, refusal, and the rest
            return reply["stop_reason"]
        results = [{"type": "tool_result", "tool_use_id": block["id"],
                    "content": tools[block["name"]](block["input"])}
                   for block in reply["content"] if block["type"] == "tool_use"]
        messages.append({"role": "user", "content": results})   # all results, one message
    return "max_turns"


def fake_model(messages: list[Any]) -> Reply:            # asks for one tool, then stops
    if len(messages) == 1:
        return {"stop_reason": "tool_use", "content": [
            {"type": "tool_use", "id": "t1", "name": "add", "input": [2, 3]}]}
    return {"stop_reason": "end_turn", "content": [{"type": "text", "text": "The sum is 5."}]}


print(run_loop(fake_model, {"add": lambda xs: str(sum(xs))}, "What is 2 + 3?", max_turns=5))
done

A response's content is an array of content blocks, each with a type that determines its shape. The loop reads each block by its type, so the text before a tool_use is never mistaken for the call.

What the loop does with each stop reason

Each row is one stop reason. The loop handles each one on purpose.

stop_reasonWhat it meansWhat the loop does
tool_useClaude is calling a tool and expects the application to run it.Run the tools it asked for. Send all the results back together. Call again.
end_turnClaude finished its response naturally.Treat it as a done claim. Check the work before you return.
max_tokensThe response reached the request's max_tokens limit.Do not run a half-written tool call. Retry with a higher max_tokens, or in smaller steps.
refusalClaude declined to generate a response, returned as a normal HTTP 200 response rather than an error.Do not retry it unchanged. Stop and report it.
pause_turnA server-tool loop reached its iteration limit.Decide on purpose: continue, or stop and report.
stop_sequenceClaude emitted one of the request's stop_sequences.Treat it as a stop you asked for. Check the reply, then decide.

Without JavaScript, the question is: a reply comes back with stop_reason max_tokens, halfway through a tool call. What should the loop do?

  1. Run the half of the tool call it has, because most of it is there.
  2. Retry with a higher max_tokens, so the whole tool call comes back. Never run the half-written call.
  3. Return the partial text as the final answer.
  4. Treat it as end_turn and check the work.

What the loop sends

The Messages API is stateless: you send the full conversational history with each request. This loop only grows the history. Each turn adds the reply and its results, and each call sends all of it. The docs say to return one tool_result for each tool_use block, all together in the next user message. A tool_result's tool_use_id is the id of the tool use request that the result answers. A tool_use block that is not run still needs a tool_result with is_error true and a brief explanation.

A loop needs more than one exit

Each way out of the loop is an exit. The loop above has two. The first is the model's done claim, end_turn. It is a claim, and nothing in this loop checks it. The second belongs to the harness: a turn limit stops the loop after a set number of model calls. A third exit you can add is a token budget: it stops the loop after a set number of tokens, input and output together. Neither harness exit depends on what the model thinks.

Why count model calls, not tool calls? Suppose one reply asks for three tools. That is still one turn, so the limit counts calls.

Where the other seven wires plug in

The other seven wires attach to the loop at fixed points. Control shapes the prompt before each call. Context & memory decides what stays in the context window. Errors & recovery decides what a failed call does. Permissions check each tool request before it runs. Verification checks the done claim. Observability records each step. The clock above shows where each one sits.

Keep it

Every run needs more than one exit.

What is a turn in the agent loop?
One call to the model, plus the tool results that follow it.
What is a turn limit?
A cap on the number of model calls in one run. The loop stops when the cap is reached.
What is a token budget?
A cap on the total tokens a run may use, input and output together. The loop checks it before each call.
What is a done claim?
The model's own statement that it finished, carried by end_turn. The loop checks it. It is not proof.
