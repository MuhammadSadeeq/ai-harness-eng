A run that says done

This is the false done from S0: the model says the tests pass, and nothing ran them. This time the question is not what happened. It is which wire is at fault.

Without JavaScript, the question is: the model says the tests pass, and nothing ran them. Which wire is at fault?

  1. Control plane: the model was told the wrong thing.
  2. Loop & state: the run should have kept going.
  3. Verification & evals: nothing checked the done claim.
  4. Observability: the run was not recorded.

The claim was the only evidence, and nothing ran the tests. The fault sits on one wire, the one that checks whether a done claim is really done. Knowing the wires is what lets you point at it.

Eight wires, one order

A harness has eight wires. Each one answers one question about a turn. In turn order they are: the control plane, which decides what the model is told and which instruction wins; context management, which decides what is on the desk this call and what is saved; the loop and state wire, which decides what happens next and when the run stops; errors and recovery, which decides how a failure is handled without spinning; tools, which decides what the model can do and whether each tool is easy to use; permissions and the sandbox, which decide which actions are allowed and how far a mistake can reach; verification and evals, which decide whether a done claim is true; and observability, which decides what exactly happened and where time and money went.

The Turn Clock draws those wires as spokes on a face, in that order, with the harness settings beside them. A turn starts at the control plane and goes all the way round. Read it as a sequence: a turn is decided in that order, so a fault on one wire shows up in the wires after it.

Why this order? The control plane comes first, because what the model is told frames the whole turn. Verification comes near the end, because a claim is checked after the work it describes. Observability comes last, because the trace records the turn after everything has happened. The order is a reading order, not a rule that each wire runs alone.

Observability is last on the clock, and it is not optional. A wire that is not in the trace cannot be blamed, and a fault that is not blamed on a wire will come back. Every wire leaves a mark in the record, so the clock and the trace are read together.

Each wire has one short law: the rule you check for that wire. Drag each law into its wire, or use its menu. Check when all eight are placed, and read the reason for each.
