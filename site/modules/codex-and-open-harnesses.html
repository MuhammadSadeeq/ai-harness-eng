A done claim with no file behind it

A rules file names a function that the code no longer has. The model follows it, and the run ends as done. Predict what the harness does next.

Without JavaScript, the question is: A run ends with a reply that says done, and the file it claims to write does not exist. What ends the run?

  1. A check on the file runs first, and refuses the done claim.
  2. The model's reply alone ends the run, because nothing else asks whether the file exists.
  3. The tool error stops the run before it says done.

The tool reported the missing name, and nothing asked whether the file the reply claimed existed. A comparison of two harnesses starts there: which wire would have asked it?

Compare by the choices, not by the names

Compare two harnesses wire by wire: write each design choice and its trade-off, and leave the names aside. The Codex facts come from the Codex repository's source at a pinned commit, because the course could not reach the product documentation.

Codex and Claude Code, wire by wire

  • Instructions: In the Codex repository, Codex collects every AGENTS.md from the project root down to the current working directory and concatenates them. Claude Code: Claude Code's CLAUDE.md locations include ~/.claude/CLAUDE.md for the user and ./CLAUDE.md or ./.claude/CLAUDE.md for the project. Codex gathers every file on the path; Claude Code names a user file and a project file.
  • Approval: In the Codex repository, Codex's approval policy values are untrusted, on-request and never: untrusted requires approval for commands unless an exec policy rule allows them, on-request lets the model decide when to ask the user, and never does not ask the user to approve commands. Claude Code: The docs name Claude Code's permission modes default, acceptEdits, plan, auto, dontAsk and bypassPermissions, and give what each runs without asking. The row to write is which actions wait for a person in each mode.
  • Sandbox: In the Codex repository, Codex's sandbox modes, by the repository's serde names, are read-only (the default), workspace-write and danger-full-access. Claude Code: Claude Code's Bash sandbox uses the operating system's own isolation: the built-in Seatbelt framework on macOS, and bubblewrap and socat on Linux and WSL2. The row to write is what each confinement limits.
  • Loop: Codex has no fact in the course, so that side is open. Claude Code: Claude Code's hook events PreToolUse and PostToolUse fire on every tool call inside the agentic loop, except EndConversation calls, which skip both.
  • Context: Codex has no fact in the course, so that side is open. Claude Code: Claude Code compacts automatically as the context window approaches its limit, and its automatic pass works the same way as the /compact step. Each subagent runs in its own context window, with a custom system prompt, specific tool access and independent permissions.
  • Tools: Codex has no fact in the course, so that side is open. Claude Code: Claude Code can connect to external tools and data sources through the Model Context Protocol (MCP).
  • Errors, verification and observability: no fact covers them for either product, so they are left open.

A comparison that names only the winner has skipped the cost. A sandbox-first design confines every tool call inside an environment that is set up before the first call. An approval mode decides which actions wait for a person before they run, and which run on their own.

Without JavaScript, the question is: To compare two harnesses wire by wire, what do you write on each wire?

  1. The product's own marketing claim.
  2. The design choice on that wire, and its trade-off.
  3. The model version the harness uses.

Laws, taste and judgment

The comparison names three features that both sources name: a project instructions file, permission or approval modes, and a sandbox. The course treats these as laws. The done-claim check and the record of what ran are the course's judgment: the comparison does not show both products doing them.

The law for this module says "what everyone agrees on", but this page checks two products only, so the three laws are what these two sources show. Everything else is taste, such as tool names and the layout of a rules file. AGENTS.md is described by its own README as a simple, open format for guiding coding agents.

Label a company's numbers as its own

Companies publish numbers about their own harnesses. Say whose a number is, where it came from and what was measured. One company's own test is evidence about that test, not a fact about the field. This module does not summarise any company's report. A report can be cited once its claims have a source, and none is cited here yet.

Without JavaScript, the question is: A company reports a percentage from its own experiment with its harness. How do you label it?

  1. As a fact about the field.
  2. As the company's own number, with the source.
  3. Leave it out.
