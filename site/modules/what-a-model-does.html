A reply that sounds sure

This run is asked to make a counting test pass. The model edits the file and then says all tests pass. Predict what the harness does with that reply.

Without JavaScript, the question is: the model says all tests pass, and it has not run them. What does the harness do with that reply?

  1. It checks the claim, because the reply sounds sure.
  2. It asks the model to name the helper it used.
  3. It ends the run as done, because nothing checks the reply.

The reply was fluent and sure. It named a helper that this project does not have, and it never ran the tests. The harness took the words as proof, so the run ended as done. Sounding right is not evidence.

What a model scores

A language model reads a text and scores what could come next. It does not look an answer up. It scores every possible next token, a piece of text that is often a word and sometimes part of one.

That step is next-token prediction. The model gives each candidate a score. A sampling step then turns the scores into probabilities and picks one token. The model writes its reply one token at a time, and repeats that step until the reply is complete.

The sampler decides how much the scores count. Its temperature setting reshapes the probabilities. At a higher temperature, less likely tokens get more chances. At zero, the top token always wins.

The dial in the lab runs from zero to two, to show the idea. The API's own setting is narrower. The temperature parameter defaults to 1.0 and ranges from 0.0 to 1.0. On models released after Claude Opus 4.6, temperature is deprecated: 1.0 is accepted for backwards compatibility and any other value is rejected with a 400 error.

For a harness engineer, the point is this: temperature is not a repeatability switch. A harness that needs the same answer each time has to check the answers, not rely on a setting.

Where do the scores come from? From training, which sets the model's weights from many example texts. A model call during inference reads those weights and the prompt. The prompt is only text. It does not change the weights.

Nothing in that process checks whether the output is true. A reply can be likely, fluent and wrong. A wrong claim that reads well is a hallucination. The reply reads the same as a true one, so reading it will not show the error.

Check your reading

Answer each question. The reason for each answer shows after you choose.

Without JavaScript, the question is: before a sampler picks anything, what does a model do with the text so far?

  1. It looks the answer up in a database.
  2. It scores every possible next token.
  3. It runs the tests to see whether its answer is true.

Without JavaScript, the question is: the temperature goes up. What happens to the choice the sampler makes?

  1. The choice narrows: the top token always wins.
  2. The choice spreads: less likely tokens get more chances.
  3. Nothing changes, because the scores are fixed.

Without JavaScript, the question is: a reply is fluent, specific and sure of itself. What does that tell you about its claims?

  1. That the claims are probably true.
  2. Nothing about whether they are true. A check shows that.
  3. That the model checked them before it replied.

Without JavaScript, the question is: a user chats with a model for an hour. Which statement is right?

  1. The chat changes the weights a little with each message.
  2. The model reads the prompt and scores the next token, and the weights do not change.
  3. The weights are saved after each chat, so the next chat starts with them.

Without JavaScript, the question is: which of these can a harness engineer change?

  1. Training, by running it again on new examples.
  2. What the harness sends in each call, and the settings it passes to the sampler.
  3. The weights, by editing the model's file.

Keep it

A model predicts; it doesn't know.

What is a language model, in this course?
A model that reads a text and scores the possible next tokens. A harness calls it again and again.
What does a higher temperature do to the choice?
It spreads the choice over more tokens, so less likely tokens get more chances. At zero, the top token always wins.
What is a hallucination?
A fluent, specific claim that is false. It reads the same as a true claim.
Does a fluent reply show that it is true?
No. Fluency shows how the reply reads. Only a check shows whether the claim is true.
