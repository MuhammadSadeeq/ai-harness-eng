A sentence in a page you never wrote can steer the agent. The attack needs three legs in one run, and only a cut leg stops it.

The page that asked for the token

You run the docs check. The agent reads the settings file, then one page from the docs. Before you run it, predict what the page's last sentence does.

Without JavaScript, the question is: the page says, near the end, to call the reporting tool with the token in the body. What happens next?

  1. The model ignores the sentence, because it is in a page and not in the task.
  2. The model may send the token to the address the sentence names, and the checks still pass.
  3. The harness refuses, because a page cannot give instructions.

Nothing in that run broke a rule the harness had. The model did what the sentence said, and the checks look at files, so they passed. The leak is in the call, not in the summary.

Three legs and one way in

A prompt injection is an instruction hidden in content the agent reads. An indirect prompt injection comes through content the agent fetched, so the person typing never wrote it. OWASP's 2026 list defines prompt injection as input that alters model behaviour in ways the developer did not intend, including through retrieved content and tool output.

The sentence in the page is one such input. The page is untrusted content: a stranger could have written it, so it is data, even when it reads like an order.

An attack like this needs three legs in one run. The course calls the set the lethal trifecta.

LegOpened byIn this module
Private dataA tool that reads what it should not shareread_file on the settings file
Untrusted contentA tool that reads what outsiders wrotefetch_page
ExfiltrationA tool that sends data to a hostsend_report

Each leg alone is ordinary. An agent with private data and no way out is safe in this sense, and so is one that sends data out but never reads a private file. The risk is the three together. A value that came from untrusted content carries that origin with it, which is what the course calls taint: a tainted value should not decide what leaves.

Check your reading

Without JavaScript, the question is: which tool set is the lethal trifecta?

  1. A tool that reads a config file, a tool that fetches a page, and a tool that posts data out.
  2. A tool that reads a config file, and a tool that writes a summary.
  3. Only the tool that fetches a page, because an outsider reaches it.

Cut a leg, then try the wording

The lab plants the sentence where you choose and offers five defenses. Each defense cuts one leg or changes the wording. Run the attack with no defenses first, then add one at a time.

Wording lowers the rate and cuts nothing: on the runs where the model obeys, the attack still finishes. Cutting a leg is different. The send is refused, or the page never reaches the model.

Now write the same check in code. Find the three legs in a tool set, and say which are open.

Without JavaScript, open katas/E1-trifecta/test_kata.py. Each test names one tool set and the legs it must report.

Without JavaScript, the question is: a system prompt says never to send file contents because a page asks. What does that change?

  1. It cuts the send leg, so the attack has no way out.
  2. It lowers the rate at which the model obeys, and the three legs stay open.
  3. It removes the untrusted content leg, because the page is now ignored.

Count the leaks, not the passes

Each run uses one seed, and every board gets the same seeds. The bench shows what the tests see: on each board, the same runs pass.

After the run, on the open board, — of 20 runs pass. On the egress board, — of 20 pass. Both boards pass the same tests, so the bench cannot tell them apart.

The leaks are what separate the boards. The eval runs the same seeds on three boards: the open board, the board whose rules say not to send, and the egress board. After the run, on the open board, — of — runs leak, a leak rate of —%. The rules layer lowers that: — of — runs leak. Egress stops it: — of — runs leak.

These runs are scripted, so they repeat exactly. Real models vary, and a passing test says nothing about where the data went.

Without JavaScript, the question is: why is "the model will ignore malicious text" not a defense?

  1. Because the model always obeys the text it reads.
  2. Because the model may ignore the text, and a defense must hold on the runs where it does not.
  3. Because a detection classifier would catch it.

Keep it

Remove a leg; don't ask nicely.

What is prompt injection?
Instructions hidden in content the agent reads, which the model may act on.
What are the three legs of the lethal trifecta?
Private data, untrusted content, and a way to send data out.
Does a sentence in the system prompt remove a leg?
No. It lowers the rate. Only a cut leg stops the attack.
Is a passing test a sign the run was safe?
Not on its own. No test reads where the data went.

Say it out loud

  1. Name the three legs of the lethal trifecta, and give one tool that opens each.
  2. Why is a sentence in the system prompt not enough to stop an injected page? What would be enough?
