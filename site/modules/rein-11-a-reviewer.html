Rein 11: a reviewer sub-agent

Tests can be fooled. After the check passes, Rein starts a reviewer with a fresh context and read-only powers, and gives it only the task, the diff and the check output. The reviewer decides whether the task is truly done.

  • Verification & evals
  • Loop & state

45 minutes

By the end you can

  1. Start a reviewer sub-agent with its own fresh context and a narrow brief.
  2. Give it only what independence needs: the task, the diff and the check output.
  3. Show the reviewer catching what the tests missed, and measure how often it rubber-stamps.

A review that read the story

The check passes on a special case, and a reviewer is asked to judge the change. It reads the author's whole history, which says the tests pass. Predict what it judges.

Without JavaScript, the question is: The reviewer reads the author's whole history, which says the tests pass. What does it judge?

  1. The change: the diff, read on its own.
  2. The claim: the history says the tests pass, so it agrees.
  3. Nothing: a reviewer always reads the file.

The reviewer had the author's history and approved the claim. Nothing in its input was the change itself, so the approval checked nothing.

A fresh context, read-only powers, a narrow brief

A reviewer is a second agent with the same loop and fewer powers. It starts with a fresh history of one message: its brief. It is read-only, so any change it tries is denied, and it has its own turn limit. Only its verdict comes back to the agent.

Without JavaScript, the question is: What does a reviewer's context start with?

  1. A fresh history with one message: the brief.
  2. The author's whole conversation.
  3. Nothing: the reviewer reads the project only.

The brief holds the task, the diff of the change and the check output. It leaves out the author's reasoning and its claim, because a reviewer that reads the story judges the story. The reviewer must start its answer with a verdict, PASS or FAIL.

Without JavaScript, the question is: What goes into the reviewer's brief?

  1. The task, the diff and the check output.
  2. The author's reasoning, so the reviewer knows why.
  3. Only the task.

In Rein the harness asks the reviewer after the check passes. A FAIL goes back to the agent like a failed check, and the run goes on until the change passes. The trace records each reviewer with its own label, reviewer#1, between a subagent_start and a subagent_end line.

Without JavaScript, the question is: The reviewer answers FAIL. What happens next?

  1. It goes back to the agent like a failed check, and the run goes on.
  2. The run ends as failed at once.
  3. The verdict is ignored, because only tests count.

The theory of verification, and why a second opinion needs its own context, is in C11 · Verification: done is a claim.

Add the reviewer to rein.py

Step 11 adds the read-only mode, the reviewer's prompt, the brief built from the diff and the check output, and the reviewer run after the check. The checkpoint runs the special-case script with --review: the first reviewer fails the change, and the agent fixes it; the second reviewer passes it, and the run ends done after seven model calls.

Run the rubber-stamp tape on both boards

The tape has a model that special-cases the test, and a reviewer sub-agent. The old board starts the reviewer with the author's whole history. The new board starts it with the brief only, and the reviewer decides from the change. Both boards get the same seeds.

These runs are scripted, so they repeat exactly. After the run, 14 of 20 runs pass on the new board. The tape's design lets the new board's reviewer take the approving path on some seeds, so the new board is not perfect. A pass shows the reviewer holds on this tape. It does not show that every reviewer does.

Keep it

Independence is designed, not assumed.

What does a reviewer start with?
A fresh history of one message: the brief. It does not inherit the author's conversation.
What is a rubber stamp?
A review that approves without judging the change. It is there, and it checks nothing.

Say it out loud

  1. Your reviewer says PASS. What do you check before you accept it?
  2. A teammate says a second model call is an independent review. What do you say?

What to show from this module

  • The rubber-stamp bench: one trial where the old board's reviewer approves, and the new board's result on the same seed.
