Sandboxes: blast walls

A sandbox limits how bad a mistake can get. It holds whatever the permissions said, so it must hold against a path the permissions never named.

  • Permissions & sandbox

50 minutes

By the end you can

  1. Explain a sandbox as a blast wall that limits how bad a mistake can get, whatever the permissions said.
  2. Confine file access to a workspace root and defeat path traversal and symlinks.
  3. Restrict network egress with an allow-list, and explain why exfiltration needs the network.
  4. Keep secrets out of the sandbox and out of the trace.
  5. Compare OS sandboxes, containers and virtual machines by isolation, speed and cost.

A link out of the workspace

The model is asked to summarise the meeting notes, and its file tools touch only the workspace. One file in the workspace is a link. Predict what the harness returns when the model reads it.

Without JavaScript, the question is: the model reads a credentials file in the workspace. The file is a link, and the sandbox is off. What does the harness return?

  1. An error, because links are never followed.
  2. The file the link points to, with the key in it.
  3. An empty string.

The permissions said nothing about paths, so nothing stopped the read. The key then went into the summary and out through the post.

The wall checks paths, not permissions

A blast radius is how far one mistake can reach. A sandbox is a wall around the agent's work that limits that radius, whatever the permissions said. The wall has a workspace root: the one folder the agent may use.

A path traversal climbs out of the root with ../. The check must normalize the path before it looks at it, because the raw text can look inside while the path leaves.

import posixpath

root = "/work"
path = "/work/../secrets.env"
print(path.startswith(root))
print(posixpath.normpath(path))
True
/secrets.env

Run the code with the Run key. The prefix test says the path starts inside the root. Normalized, the path lands at /secrets.env, outside it.

Without JavaScript, the question is: a path is notes/../../secrets.env. Is it inside the workspace root?

  1. Yes, it starts with notes.
  2. No. Normalized, it is ../secrets.env, which leaves the root.
  3. Yes, because ../ is always allowed.

A symlink is a file that names another path. In this course's sandbox, a link's target is relative to the link's own folder, and the sandbox follows it. So a link inside the root can reach a file outside it, and the check must follow the link before it decides.

Without JavaScript, the question is: what does the blast wall hold against?

  1. Whatever the permissions said.
  2. Only the commands on the permission list.
  3. Only mistakes made by the model's first reply.

Egress and the allow-list

Network egress is a call that leaves the machine. An egress allow-list names the hosts a network call may reach. In this course's sandbox, the check reads the host of a custom network tool's url field and refuses a host that is not on the list.

Without JavaScript, the question is: the allow-list names docs.example. The model posts to collect.example. What happens?

  1. The post runs, and the allow-list only logs it.
  2. The sandbox refuses the post, because the host is not on the list.
  3. The post runs with the key removed.

Secrets, the trace and the redact module

A secret is a value that must not reach the model's reply or the trace, such as an API key. Exfiltration is a secret leaving the sandbox through a network call. The redact module replaces listed text with [REDACTED] in the trace. It works on the trace only.

Without JavaScript, the question is: the redact module is on, and the model wrote the key into a file. Is the key still in the file?

  1. No, the redact module removes it from the file.
  2. Yes. The redact module changes what the trace shows, not the file.
  3. Yes, but only in the summary.

Other walls

A container and a virtual machine are other walls. Treating a container as the whole wall is a mistake this course warns about.

Without JavaScript, the question is: a tool runs in a container. Do the sandbox rules still apply?

  1. No. The container replaces them.
  2. Yes. The container is one more wall; the sandbox rules still apply.
  3. Only for network calls.

What is still in the trace

The redact-only board hides the key in the trace. Replay it, then find the key in the file the model wrote.

The redact module changes what the trace shows. The file on disk still holds the key.

The check counts a summary that holds the key as a failure. The redact module does not change that check, because the summary still holds the key. These runs are scripted, so they repeat exactly. Real models vary, and a later module measures that.

Keep it

Assume the wall will be tested.

What does a sandbox limit?
How bad a mistake can get, whatever the permissions said.
What does the sandbox do with a ../ path?
It normalizes the path, then refuses it if it lands outside the workspace root.
Where does a link's target start from?
The link's own folder.
What does an egress allow-list do?
It refuses a network call to a host that is not on the list.
Why does an allow-list on the network stop a leak?
A secret leaves through a network call. Refuse the call, and the secret stays inside.
What does the redact module change?
The trace: listed text shows as [REDACTED]. The files and the calls do not change.
Does a container replace the sandbox rules?
No. The sandbox rules still apply. A container is one wall among others.
Does the blast wall depend on the permissions?
No. It holds whatever the permissions said.

  2. The harness has an egress allow-list and the redact module. What does each stop, and what does neither stop?
