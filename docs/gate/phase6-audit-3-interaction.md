# Phase 6 audit 3: interaction QA (BP-6.0 section 3)

Reviewer: hx-reviewer 3 (interaction QA). Audited commit: 0fef4ca.
Worktree: `scratchpad/audit-3` (clean at 0fef4ca; untracked only the `.venv` and `node_modules` symlinks). Scratch: `scratchpad/audit-scratch-3`. No project file was edited, created or deleted; QA output went to scratch (`--out`), not `tools/qa/out`.
Judged against `docs/COMPONENTS.md` in the audit worktree (the audited commit). The main tree's copy has since gained a D-061 section 5 (per-component credit rules); that text is not in 0fef4ca and is not judged here.
Severity counts: 11 major, 3 minor.

Most important finding: keyboard focus is lost to BODY after the main action in 10 components (shift, envbuilder, evalbench, escape, topology, design, cards, stack, replay, clock, wire). The focus fix-up in `lib/hx-element.js` cannot restore focus to a control that was disabled or hidden by the press, or that was rebuilt without a `data-key`.

## Findings

### Major

- [major] `site/assets/components/hx-cards.js:318-323` (ordering card's "Check", `data-key="check"`); the checked branch renders "Next" (`data-key="next"`) and nothing moves focus — focus goes to BODY after Check. The reveal path does it right (`focusBack: true`, `hx-cards.js:289`). Evidence: `scratchpad/probe-cards-check.mjs` on `modules/prompt-caching.html`, deck walked with real keys to the ordering card: `before: focus button data-key=check "Check"`; after Enter: `check buttons=0, next buttons=1; focus BODY ""`. Keyboard walk logged it too. Suggested fix: focus Next (or the verdict line) when Check is replaced.

- [major] `site/assets/components/hx-incident.js:169` (`heading.scrollIntoView({ block: "start", behavior: reduced() ? "auto" : "smooth" })`) with `reduced()` at `:28` reading only the system media query. A learner who set "Reduce motion" on in the site settings (stored pref, `data-motion="reduced"`) still gets a smooth scroll when the hunt is found. Binding rule: COMPONENTS §6, "reduced motion (pref or system) removes travel". Evidence: `scratchpad/probe-motion.mjs` on `modules/prompt-caching.html`, real clicks on the toggle and real keys for the hunt: stored on + system no-preference: `html data-motion=reduced; toggle label="Reduce motion: on"`, `smooth scrolls: 1`; system reduce only: `auto`, `smooth scrolls: 0`; stored full + system reduce: `auto`. Suggested fix: read the stored pref through `this.reducedMotion` (the base class getter) instead of the media query.

- [major] `site/modules/interview-room.html:204-205` (`<hx-cards src="I5"></hx-cards>`, `<hx-say src="I5"></hx-say>`) and `site/oncall.html:71` (`<hx-cards src="board"></hx-cards>`): no authored children, so with JavaScript off the cards, the say-it prompts and the shift drill are blank. AUTHORING.md:208-209 ("Every component in a page must contain its no-JS fallback as children: a static figure or table plus a sentence") and COMPONENTS.md §2 require it. Evidence: `scratchpad/nojs-run.log`: `ISSUE modules/interview-room.html {"status":200,"words":979,"empty":["hx-cards text=\"\" h=0","hx-say text=\"\" h=0"]}`, `ISSUE oncall.html {"status":200,"words":75,"empty":["hx-cards text=\"\" h=0"]}`. The other 106 pages (820 hx-* elements) have a visible fallback for every component. Suggested fix: add a figure or list and one sentence inside each element (for I5 and board).

- [major] `site/assets/components/hx-step.js:204-205` and `hx-wire.js:407-409`: copy calls `writeText(...).catch(() => {})` and announces and shows "Copied" whatever the outcome, so a refused write still reads as copied. Evidence: `scratchpad/probe-copy.mjs` (instrumentation: `writeText` replaced by a stub that rejects with NotAllowedError, as a denied permission would; the component code runs unchanged): `labs/step.html (hx-step): copy key after Enter shows "Copied"; live="Copied"; writeText calls=[...] (all rejected by the stub)`; the same on `labs/wire.html`; no error logged. A learner who pastes after this gets the old clipboard. Suggested fix: announce "Copied" only after the promise resolves; on rejection say "Could not copy. Select the text and copy it."

- [major] `site/assets/components/hx-shift.js:224` (Run: `disabled: s.running`, label "Start the next shift") and `hx-shift.js:270` (`this.ui.replaceChildren` on every render). Same pattern: `hx-envbuilder.js:300` and `:341` ("Run the policy"); `hx-evalbench.js:393-397` (`disabled: !canRun`, `canRun` false while running, `:364`) and `:475`; `hx-escape.js:354` ("Replay the attack", `disabled: s.running`) and `:384`. Pressing Run disables it, the render rebuilds the UI, and the focus fix-up cannot focus the disabled button, so focus goes to BODY. Evidence: `scratchpad/probe-focus-run.mjs` (Tab to the control, Enter, state after 400 ms): `shift run: ... focus BODY ""`, `envbuilder run: focus BODY ""`, `evalbench run: focus BODY ""`, `escape replay: focus BODY ""`. `scratchpad/probe-focus-trace.mjs` (DOM observer): `blur on control` and `focusout from control (related=null)` at 3-4 ms, then `removed 3-5 node(s) from div.hx-ui` per render, with the original control `connected:false`. After Enter, the next Tab lands on the note textarea, then on Run again (`scratchpad/probe-tab-after.mjs`). Keyboard walk (`scratchpad/probe-keys.mjs`, batch 3): lostToBody shift 199, envbuilder 99, escape 57, evalbench 44. Suggested fix: while running keep the control focusable (`aria-disabled` only, click ignored), or move focus to the progress line and make it `tabindex="-1"`.

- [major] `site/assets/components/hx-topology.js:222` (the Isolated / Forked context toggles have `aria-pressed` and `data-context` but no `data-key`) and `hx-topology.js:236` (the whole `this.ui` is rebuilt on each change): every toggle drops focus, and there is no key to restore it to. Evidence: `scratchpad/probe-focus-run.mjs`: `topology Isolated: ... focus BODY ""`; trace: `focusout from control (related=null)` at 3 ms, then `removed 13 node(s) from div.hx-ui`. Keyboard walk on `labs/topology.html`: lostToBody=199 (the same control each time). Suggested fix: give each toggle a `data-key` and do not rebuild it on a selection change.

- [major] `site/assets/components/hx-replay.js:552` (`r.showAll.hidden = !shown;`; button built at `:396-397`, `data-key="show-all"`): "Show all" clears the wire filter and hides the button that was just pressed, so focus goes to BODY. Evidence: `scratchpad/probe-showall.mjs`, keyboard only, on `labs/replay.html`: Enter on the "Control" lane label, Tab x10 to "Show all", Enter -> `focus BODY ""; show-all hidden=true; filter line "Showing: all eight wires."`; the next Tab lands on the Transcript region. Keyboard walk logged it four times. Suggested fix: keep the button in place, disabled, while no wire is filtered, or move focus to the run-position slider when it hides.

- [major] `site/assets/components/hx-clock.js:387` (`button.disabled = this.state.plugged`, the "Plug it in" button, `data-key="plug"`, built at `:386-388`): the button disables itself on activation and focus goes to BODY. Evidence: `scratchpad/probe-disable.mjs` on `labs/clock.html`: Enter on `[data-key="plug"]` -> `text "Plugged in" disabled=true; focus BODY ""`. Keyboard walk logged it twice. Suggested fix: keep the button focusable (`aria-disabled`), or move focus to the plugged status line or the first spoke.

- [major] `site/assets/components/hx-wire.js:150` (`back.disabled = this.state.turn <= 1`, Previous) and `:157` (`forward.disabled = this.state.turn >= this.turns`, Next): the control disables at the end of the range and focus goes to BODY. Evidence: `scratchpad/probe-disable.mjs` on `labs/wire.html`: `start "Turn 3 of 6"`; Enter on Previous -> `"Turn 2 of 6"`, focus on turn-back; Enter again -> `"Turn 1 of 6"; back disabled=true; focus BODY ""`. Keyboard walk logged it once. The Next case uses the same code at `:157` (not run). Suggested fix: as for hx-clock.

- [major] `site/assets/components/hx-design.js:363` (`dom.reveal.hidden = s.revealed`, "Show the model answer") and `:366` (`dom.again.hidden = !s.revealed`, "Try again"): each button hides itself when pressed and focus goes to BODY. Evidence: `scratchpad/probe-focus-run.mjs`: `design reveal: ... "hidden":true; focus BODY ""`. Keyboard walk on `labs/design.html`: lostToBody=2 (reveal, again). Suggested fix: move focus to the next step (the model answer heading or "Save my grade") when a control hides.

- [major] `site/assets/components/hx-stack.js:240-241` (`dom.next.hidden = !d.revealed`, "Next conflict"): the button hides as soon as the next conflict is shown, and focus goes to BODY. Evidence: `scratchpad/probe-stack-next.mjs` on `labs/stack.html`, keyboard only: `after enforce: next visible=true text="Next conflict"`; `after Enter on Next: next hidden=true; focus BODY ""`. Suggested fix: as for hx-design, move focus to the new conflict heading.

### Minor

- [minor] `site/assets/components/hx-bench.js:648` (`dom.run.setAttribute("aria-disabled", String(locked || s.running))`): a locked or running Run gets `aria-disabled` only, not the `disabled` attribute COMPONENTS §10 names ("disabled (not hidden)"), and hx-replay (`hx-replay.js:539`) uses `disabled`. The control stays in the tab order, Enter does nothing, and the lock line explains it. Evidence: `scratchpad/probe-locked-run.mjs` on `labs/check.html` (`bench1` locked): focus stays on Run after Enter, lock line "Make your prediction above to unlock the run."; the grep shows only `aria-disabled` is set. Suggested fix: set `disabled` as well, or record in COMPONENTS §10 that aria-disabled is the intended form.

- [minor] `site/assets/components/incident.css:34`, `replay.css:44`, `evalbench.css:62`, `escape.css:53` (`@media (prefers-reduced-motion: reduce) { ... { transition: none !important; animation: none !important; } }`): these override a learner's explicit Full choice when the system asks for reduced motion. Only hover and focus transitions are lost (no other transitions are declared in these four files). Evidence: `grep -c transition` on the four files returns only these rules; the `:root:not([data-motion="full"])` guard in `core/hx.css:338` is not applied to them. Not probed in a browser. Suggested fix: scope these to `:root:not([data-motion="full"])`.

- [minor] `site/assets/components/hx-incident.js:219-226` (`saveHunt`, called only when a hunt finishes): partial hunt progress (wrong taps, the "Too early" / "Too late" feedback, the hint) is not kept across a reload, so a reload restarts the hunt. No error, no double credit. COMPONENTS §5 gives `hunts[<tape id>]` as an example of restored state. Evidence: `scratchpad/probe-hunt-reload2.mjs` on `modules/prompt-caching.html`: `before reload: marks=5` (feedback lines "Too early" / "Too late" after four taps), `after reload: marks=0`; `localStorage` holds no `hunts` entry until the hunt finishes. Suggested fix: save the partial hunt, or document in COMPONENTS §5 that only finished hunts are restored.

## Limits

- The keyboard walk is generic: Tab, Enter, Space, arrows. It reached the controls Tab reaches. Some main paths need specific keys not walked: hx-sort reordering, hx-kata memory mode, hx-clock spoke arrows, hx-gatekeeper rounds, hx-outage presets, hx-cacheline blocks, hx-bugcatch cells beyond their first. The QA self-tests drive those main paths with clicks, not keys.
- Chromium only (Playwright 1.56.1, headless). No screen reader, no Firefox or Safari. Copy behaviour in other browsers may differ.
- The copy finding uses an instrumentation stub (`writeText` rejects with NotAllowedError, labelled as such); the component's own code runs unchanged. A real denial was not triggered.
- The scroll finding reads the `behavior` argument of `scrollIntoView` (instrumented), not a captured animation frame.
- The stack finding is reproduced in isolation (`probe-stack-next.mjs`).
- The bench reload mid-run could not be caught (the run finished before the reload); reload mid-run is therefore not covered for bench.
- The replay determinism difference was not isolated (real-time playback during the walk).
- Kata test results were not judged for correctness (reviewer 1 and 5 scope); only that the runs report.
- The stored-Full CSS minor (`incident.css:34` and the others) was not probed in a browser; it rests on the CSS text.
- Other agents ran browser checks on this machine (load up to 13); two QA views timed out under that load and passed alone. Run 1 of the QA stopped at its 2 h background limit; run 2 covered the rest.
- Judged against the worktree `docs/COMPONENTS.md` at 0fef4ca; not against the main tree's newer D-061 text.

## 3-line summary

1. Findings: 11 major, 3 minor. The most important: keyboard focus is lost to BODY after the main action in 10 components (shift, envbuilder, evalbench, escape, topology, design, cards, stack, replay, clock, wire).
2. The most important one for a learner: "Copied" is announced when the clipboard write was refused (`hx-step.js:204-205`, `hx-wire.js:407-409`), so a learner pastes stale text without knowing.
3. QA over all 108 pages: 0 failures on the final pass (2 load timeouts passed alone); seeded determinism holds on 12 labs; the no-JS pass has 2 pages with blank cards (`interview-room.html`, `oncall.html`).
